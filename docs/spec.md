# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

飲み会の割り勘を先輩・後輩の傾斜つきで1分で決めて、そのままLINEに貼れる文面にしてくれるWebアプリ（元のメモ：飲み会の割り勘を、先輩・後輩の傾斜つきで1分で決めて、LINEに貼れる文面にするWebアプリ）

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 使う人：会社の課・部活・サークルの飲み会の幹事（たいてい若手）。先輩・上司が多めに払う「傾斜」をつけたい
  - 使う場面：会計の直後、店の前や2次会への移動中に、スマホで合計を入れて坂を決め、そのまま LINE のグループに文面を貼る
  - 1回1分。登録もログインも無い
- 技術：Next.js（App Router）＋TypeScript、テストはVitest

## 画面

（ページごとに、何を出して何ができるか）

### 続きから使える（入れた会を端末に残す）

- 残す先は、この端末のブラウザ（`localStorage`、キー `senpai-warikan:v1`）だけ。サーバーには送らない。1つの会（最後に入れた会）だけを上書きして残す
- 残す中身：会の名前・合計（数値）・メンバー（id・名前・立場・主役）・坂の急さ・丸め・幹事・端数を持つ人・期限・選んでいるメンバー。開いている欄（会の決まりの編集中など）は残さない
- 残す時：読み込みが終わったあと、入力が変わるたびに保存する。読み込む前に例の会で上書きしない
- 読む時：最初の描画はサーバーと同じ例の会。そのあと（`useEffect`）で、残した中身があれば画面に反映する
- 残した中身が読めないとき（JSONが壊れている・形が違う・立場が1〜5でない・丸めが100/500/1000でない・坂の名前が無い・メンバーが0人または20人超・幹事や選択中のメンバーがメンバーにいない など）は捨てて、例の会のまま開く。`localStorage` が使えなくても落ちない（残せないだけ）
- 「例の会。伝票の金額に書き換えてください」「例：」は、会の名前・合計・メンバーが最初の例の会と同じ中身のときだけ出す（読み込み後も同じ判定）。書き換えて再読み込みしたら出ない
- 「新しく足した人」の id（`new-N`）は、読み込んだメンバーの id とぶつからないように決め直す

### 坂の柱をつかんで段を変える

- 対象：坂の柱（`SlopeChart` の `step`）。ポインター操作（マウス・タッチ・ペン）で、柱を押したまま動かすと、その人の立場の段（`Level` 1〜5）が変わる。ライブラリは使わず Pointer Events で書く
- 動かす向き：段が上がる向きが正。PC（柱が縦）は上に動かすと段が上がり、下に動かすと下がる。スマホ（720px 以下。柱が横向きの棒）は右に動かすと上がり、左で下がる（長さ＝払う額の向き）
- 1段ぶんの距離：柱の高さ（スマホは棒の置き場の幅）を5で割った長さ。24px 未満にはしない。つかんだ位置から1段ぶん動くごとに1段切り替わり、5より上・1より下にはならない（`src/lib/drag.ts` の `levelFromDrag`）
- 6px 動くまでは「押しただけ」。動いたら、その柱を選んだ状態（`is-sel`）にし、動かした結果は ▲▼ と同じ状態更新に流す。金額・均等との差・LINE の文面は `computeSplit` でその場で再計算される（計算は変えない）
- 動かさずに離したときは、今までどおり押して選ぶだけ。動かして離したときは、続けて選び直す押下は起きない
- 主役（`guest`）の柱は段の対象外。動かせず、押して選ぶだけ
- 縦スクロールを邪魔しない：つかむ動きは柱の上だけで受ける（PC は `touch-action: pan-x`、スマホは `pan-y`）。キーボード操作（編集の列の ▲▼）と柱の `aria-label` は今までどおり
